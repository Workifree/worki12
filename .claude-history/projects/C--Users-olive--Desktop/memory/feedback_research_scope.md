When the user asks for research, research EXACTLY what they asked. Do not expand scope to "related" topics they mentioned in passing.

**Why:** The user said "you don't have to search PWA retarded. PWA runs anywhere i wanted to example to you that we dont need much to run focus on..." — they were frustrated that I added "PWA performance optimizations" as a research topic when they only mentioned PWA as an example of what they want to run on the device. They wanted research focused on the actual problem (Magisk SU hang) and on the best OS for the hardware.

**How to apply:** When the user gives an example or use case, treat it as a constraint, not a research target. Research the system/blocker, not the example workload. If they say "I want to run X on this device", focus research on the device and the blockers, not on X.
